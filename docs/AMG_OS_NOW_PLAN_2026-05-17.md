# AMG OS NOW Plan

Date: 2026-05-17

## Governing Priority

AMG OS is the immediate business goal.

The current priority is not to build a polished public SaaS first. The priority is to make AMG's internal operating system work for Amy and Mario now, reduce workflow waste, standardize task execution, control agent/tool usage, and eliminate hidden payroll/tool inefficiency.

`AMG_OS` is the NOW lane.

`AMG_OS_NEXT` is the future productization lane and should absorb proven internal workflows only after they work in the real AMG business.

## Business Problem

AMG is operating in a difficult market with costly workflow issues:

- manual cover/keyframe selection
- scattered delivery materials
- repeated metadata work
- unclear handoffs
- inconsistent employee/contractor execution
- hidden AI-agent/tool use outside central control
- payroll spent on avoidable research, admin, and rework
- weak proof that a task was completed correctly

The internal OS must reduce those costs before the SaaS story matters.

## NOW Mission

Build AMG OS as Amy's internal command system:

- one workflow map
- one source of truth for deliveries
- one place for review status
- one place for AI-agent outputs
- one handoff protocol for employees/contractors
- one archive and evidence trail
- one cost/time-saving dashboard

## Priority Stack

1. Stabilize `AMG_OS` v11.x as the real working engine.
2. Preserve Noah's keyframe/model-learning work as a reference track.
3. Clean and route mixed repo material into correct lanes.
4. Build/finish the internal AMG workflow console before public SaaS polish.
5. Define approved AI-agent task packets for AMG workers.
6. Track task cost, tool usage, human review, and completion proof.
7. Promote proven internal workflows into `AMG_OS_NEXT` later.

## What Belongs In AMG_OS Now

- v11.x cover/keyframe processing
- Amy delivery workflows
- metadata and title translation tasks needed for real deliveries
- internal review gates
- local business workflow automation
- Noah keyframe findings after synthesis
- operator dashboard for today's business

## What Belongs In AMG_OS_NEXT Later

- SaaS architecture
- KEYFRAME Suite commercialization
- TSS / NOXOvision competitor positioning
- external customer portal
- multi-tenant product concerns
- public pricing/packaging
- polished investor/customer artifacts

These are not discarded. They are deferred until the internal system proves operational savings.

## Agent Routing Rule

Codex manages the command center and verifies state.

Claude writes synthesis, policy, workflow maps, and decision docs.

Cursor edits code, runs tests, and prepares commits.

No agent should be asked to "understand everything" in a single open-ended chat. Every agent gets a bounded task packet with exact inputs, exact output path, and cleanup instructions.

## Corrective Action

Treat `AMG_OS` as a mixed workspace requiring triage:

- keep real v11.x code and delivery tooling
- move SaaS planning docs to `AMG_OS_NEXT` or archive
- stage temporary manifests/logs/browser state outside the repo
- synthesize Noah/keyframe findings before promotion
- commit only focused, testable changes

## Definition Of Progress

Progress is not more plans.

Progress is:

- one workflow made faster
- one repeated manual task removed
- one handoff made clear
- one employee/contractor task made auditable
- one delivery made cleaner
- one cost leak closed
- one verified artifact saved in the correct place
